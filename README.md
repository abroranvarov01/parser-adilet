# Сборщик законодательства РК (old.adilet.zan.kz) для Traffic Law RAG

Собирает действующие документы (`st=new|upd`) на **русском (ru) и казахском (kk)** языках, сохраняет
оригиналы и превращает каждый документ на каждом языке в **один полный `.md`** под существующий загрузчик (`DirectoryLoader` + `TextLoader`,
`**/*.md`, `MarkdownHeaderTextSplitter` по `#`…`####`). Чат, поиск, промпты, embeddings и базы
Chroma не затрагиваются. Загрузчик `embending_ru.py` жёстко ставит `jurisdiction="UZ"` —
для Казахстана его не запускать.

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Все команды запускаются из корня проекта. Данные — в `./data` (меняется `--data-dir`).

## Команды

Пробный сбор (2 страницы каталога, до 20 документов; ID разных типов — первыми):

```bash
.venv/bin/python -m adilet_collector pilot --ids K1400000235,Z1400000194,P2300000758
```

Полный сбор ru + kk (общая очередь с чередованием языков, общий лимит на домен, адаптивная
параллельность 2 → 4 → 8). Эта же команда продолжает сбор после остановки:

```bash
nohup .venv/bin/python -m adilet_collector crawl --langs ru,kk > data/crawl.log 2>&1 &
```

Быстрый вариант: документы через API adilet.zan.kz (каталоги по-прежнему с разрешённых страниц old.adilet).
**robots.txt adilet.zan.kz запрещает `/api/`** — режим включается только явным флагом оператора:

```bash
nohup .venv/bin/python -m adilet_collector crawl --langs ru,kk --doc-transport api --i-accept-api-robots-risk > data/crawl.log 2>&1 &
```

В режиме API: сохраняется исходный JSON (`raw/<lang>/{id}.api.json.gz`), проверяются `group_number` = запрошенный ID,
`language` = `rus`/`kaz`, непустой `text_content`, `is_stub`/`has_content`, язык текста; при ошибке или заглушке
документ берётся со страницы old.adilet (`--no-api-fallback` отключает). Лимиты (`--rps`, параллельность, пауза
при 429) — те же общие. Уже готовые документы повторно не скачиваются.

Только один язык: `--langs ru` или `--langs kk`. ID для конкретного языка: `--ids kk:Z1400000194`.

Остановка: `Ctrl+C` / `kill -INT <pid>` — незавершённые документы возвращаются в очередь.
Повторный запуск `crawl` пропускает готовые документы и страницы каталога.

Повтор ошибок (загрузки — в очередь, извлечения — переконвертация из оригинала, каталог — страницы с ошибкой):

```bash
.venv/bin/python -m adilet_collector retry-failed --kind all
.venv/bin/python -m adilet_collector crawl
```

Повторная конвертация сохранённых HTML без сети (после исправления парсера):

```bash
.venv/bin/python -m adilet_collector reconvert
```

Статистика отдельно по языкам и отчёт о полноте (`data/reports/`, не в корпусах):

```bash
.venv/bin/python -m adilet_collector stats --langs ru,kk
```

```bash
.venv/bin/python -m adilet_collector report
```

Сверка каталога (новый проход: добавит новые ID, готовые документы не скачивает повторно):

```bash
.venv/bin/python -m adilet_collector recheck-catalog
```

### Полезные параметры `crawl`

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `--rps` | 2.0 | общий лимит запросов/с на домен (каталог + документы + приложения + повторы) |
| `--start-concurrency` | 2 | стартовая параллельность |
| `--max-concurrency` | 8 | потолок авто-повышения; выше 8 — только с `--i-measured-above-8` |
| `--with-info` | выкл. | также вкладка «Информация» (дата принятия/изменения/публикации); +1 запрос на документ |
| `--langs` | ru,kk | языки сбора |
| `--publish-incomplete` | выкл. | документы с непрочитанными приложениями — в корпус вместо `data/incomplete/<lang>` |
| `--fetch-attachments` | выкл. | скачивать приложения, разрешённые robots.txt |
| `--transport curl` | aiohttp | резервный транспорт (curl через subprocess, без shell) |
| `--max-pages`, `--max-docs`, `--ids`, `--no-catalog` | | ограничения для проверок |

Второй экземпляр на тех же данных запустить нельзя (файловая блокировка) — лимиты всегда общие.

## Результат

```
data/
  adilet_ru/            готовые проверенные .md на русском: {document_id}_{название}.md
  adilet_kk/            то же на казахском
  incomplete/{ru,kk}/   текст проверен, но есть непрочитанные содержательные изображения/файлы
  metadata/{ru,kk}/     {document_id}.json — метаданные, проверка полноты, предупреждения
  raw/{ru,kk}/          оригиналы {id}.html.gz (и {id}.info.html.gz при --with-info)
  catalog_raw/{ru,kk}/  страницы каталогов
  attachments/{ru,kk}/  скачанные приложения (если включено и разрешено)
  quarantine/{ru,kk}/   {id}/ — ошибки извлечения и документы со статусом «на проверку»
  backups/              резервные копии state.sqlite перед миграциями
  reports/              отчёты
  state.sqlite          каталоги, очередь, состояния, ошибки; ключ source + document_id + language
```

Метаданные: `source_system: "adilet"`, `jurisdiction: "KZ"`, `language: "ru" | "kk"`. Название, статус и даты
каждого языка берутся только со своей страницы; статусы языков реально различаются (например,
K2600000000: ru «Исправление ошибки», kk «Жаңа»; K1400000235 — наоборот).

Состояния документа: `discovered`, `downloading`, `downloaded`, `parsed`, `validated` (полностью
извлечён), `incomplete` (текст проверен, но есть изображения/файлы, чьё содержимое не извлечено;
сохраняется в `data/incomplete/<lang>`, не в корпусе), `review` (статус на странице не
«Новый/Обновленный» или расходится с карточкой — в `quarantine`), `failed` (`error_kind`:
`download` или `extract`).

## Как устроено и что проверено на реальном сайте

* **Казахский каталог:** `/kaz/search/` запрещён так же; разрешённый
  `/kaz/index/docs/st=new%7Cupd&pagesize=100&sort_field=dt&sort_desc=false&page=N` проверен: фильтр
  «Мәртебесі ( Қолданылып жүрген )», 130 853 док., 1 309 стр., ссылки `/kaz/docs/{ID}`. Казахский каталог
  обходится самостоятельно (состав отличается от русского). Казахская структура: «І бөлім», «1-тарау»,
  «1-бап», «…қаулысына 1-қосымша».
* **API нового сайта** (`adilet.zan.kz/api/documents/by-ngr/{id}?language=rus|kaz`): robots.txt нового домена
  содержит `Disallow: /api/`, страницы документов там — SPA без текста. По умолчанию транспорт — old.adilet;
  API — только с `--doc-transport api --i-accept-api-robots-risk`. Поля JSON названы обманчиво: `title_ru` —
  название **на языке документа**, `title_kz` = `official_name` — строка реквизитов на языке документа
  (проверено на 200 документах ru/kk: ни одного расхождения с карточкой каталога). У kk `adoption_date` может
  быть пустым. Даты API сохраняются исходными строками; календарная дата = UTC+6 ч (источник хранит местную
  полночь: 2026-03-14T18:00Z = 15.03.2026), с проверкой по реквизитам каждого документа — расхождение
  (например, V1500012590: API 28.12.2015, реквизиты 11.12.2015) пишется в `warnings`. `created_at`/`updated_at`
  — метки записи, не даты изменений. `is_actual` не считается доказательством юридической силы.
* **Сверка old.adilet ↔ API** (17 документов ru/kk): 16 — Markdown идентичен посимвольно; kk K1400000235 —
  разные редакции источника (API новее: «заңдарында» → «заңнамалық актілерінде», статус `upd` против
  «Қатені түзеу»), а также другой формат якорей ссылок (`#64` вместо `#z64`, одна битая ссылка в API) —
  сохраняется как в источнике. Значение языка для
  казахского — `kaz` (клиентский код сайта: `{ru:"rus", kz:"kaz", en:"eng"}`; проверено одним запросом:
  `language:"kaz"`, казахский текст). `text_content` API совпадает с HTML старого сайта: Markdown
  K2600000000 идентичен на обоих языках.
* **robots.txt** запрещает `/rus/search/` и `/files/`. Каталог берётся с разрешённого
  `/rus/index/docs/st=new%7Cupd&pagesize=100&sort_field=dt&sort_desc=false&page=N` — та же выдача
  («Статус ( Действующий )», 133 203 док., 1 333 стр. на 17.10.2026). Сортировка по дате принятия
  по возрастанию: новые акты добавляются в конец. Ссылки — только из `.serp .post_holder .post_header a`.
  Приложения из `/files/` по умолчанию не скачиваются (ссылки и статус сохраняются).
* **Проверки каталога:** номер страницы, применённые фильтр/сортировка/размер выдачи, различение
  «следующей» и «последней» `nextpostslink`, пустая страница ≠ конец, совпадение с предыдущей
  страницей, изменение общего числа документов во время обхода; считаются уникальные ID.
* **Текст** — `.container_gamma.text article`; название, статус и реквизиты —
  `.container_alpha.slogan`. Скрипты и реклама (adfox) удаляются; примечания ИЗПИ/РЦПИ и сноски остаются.
* **Markdown:** `#` название, `##` раздел/часть/приложение, `###` глава (и `<h3>` вида «1. Общие
  положения»), `####` статья. Параграфы и более глубокие уровни остаются в тексте. Простые таблицы —
  Markdown, таблицы с `rowspan/colspan` — HTML. `128<sup>3</sup>` → `128³`, буквенные индексы —
  `Т<sub>ср</sub>`. Ссылки абсолютные. Изображения — `![](url)` на своём месте.
* **Проверка полноты** независима от генератора: слова исходного контейнера (включая текст ссылок,
  ячеек таблиц и индексы) сравниваются со словами, извлечёнными из готового Markdown; отдельно —
  заголовки статей, числа и остатки интерфейса. Любая потеря → `quarantine`.

## Скорость

Сервер отвечает на любую динамическую страницу примерно за **30 с** (это задержка самого сайта:
одинаково для curl и aiohttp, с cookies и без, robots.txt отдаётся за 1–2 с). Параллельные запросы
не встают в очередь, поэтому скорость ≈ параллельность / 30 с. Измерено на 60 документах:

| Параллельность | Полезная скорость | Медиана задержки |
| --- | --- | --- |
| 2 | 3,3 док/мин | 29–33 с |
| 4 | 6,8 док/мин | 31 с |
| 8 | ~16 док/мин | 30 с |

Через API (измерено на 200 документах ru/kk, `--rps 2`): ~120 док/мин при медиане ответа 0,3–0,4 с, без
ошибок и 429; скорость упирается в общий лимит 2 запроса/с, поэтому контроллер оставил параллельность 2
(уровень 4 прироста не дал). Оценка для ru+kk (~264 тыс.): ≈ 37 ч загрузки документов; каталоги (≈2 640 стр.
по ~30 с на old.adilet) обходятся параллельно и находят ~200 док/мин, то есть не тормозят. Итого ≈ 1,5–2 суток.
Ускорить можно только повышением `--rps` — это решение оператора.

Через old.adilet, ориентировочно (оценка, не обещание): ru ~133 тыс. + kk ~131 тыс. ≈ 264 тыс. документов при 8 потоках
≈ 275 ч (~11–12 суток); только ru ≈ 6 суток. С `--with-info` — примерно вдвое дольше. Второй язык не
удваивает нагрузку: лимиты общие, просто очередь вдвое длиннее. Частота при этом ≈ 0,27 запроса/с — намного ниже лимита
2 запроса/с; ограничивает именно задержка сервера. Поднять параллельность выше 8 можно только явно
(`--max-concurrency 16 --i-measured-above-8`), после собственных измерений.

## Ограничения полноты

* Содержимое изображений и файлов-приложений не извлекается (OCR нет); такие документы — `incomplete`.
  Декоративными (не влияющими на полноту) считаются только линии/распорки (сторона ≤ 3 px) и маркеры
  (≤ 12 px); значки ~20 px неотличимы от символов формул без просмотра файла и считаются содержательными.
* Казахские версии есть не у всех актов (например, kk:E84425284AD → 404), и наоборот.
* Выдача может меняться во время многодневного обхода; дедупликация и `recheck-catalog` уменьшают,
  но не исключают пропуски.
* Даты изменения/публикации есть только с `--with-info`; дата вступления в силу не вычисляется —
  сохраняются исходные формулировки (`dates.entry_into_force_raw`).
* Оглавления-ссылки сайта (`…/k14235.htm`) не скачиваются: это служебные страницы ИЗПИ, не текст акта.
