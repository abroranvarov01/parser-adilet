# Сборщик законодательства РК (adilet) для Traffic Law RAG

Собирает **все доступные документы независимо от статуса** (действующие, утратившие силу, прекращённые,
с исправлениями и др.) на **русском (ru) и казахском (kk)** языках с adilet.zan.kz: каталог — через
`POST /api/search`, документы — через `GET /api/documents/by-ngr/{id}`. Каждый документ на каждом языке —
**один полный `.md`** (UTF-8) для существующего загрузчика (`**/*.md`, заголовки `#`…`####`, нарезка 1200/200
делается загрузчиком). Чат, поиск, промпты, embeddings и Chroma не затрагиваются; `embending_ru.py` жёстко
ставит `jurisdiction="UZ"` — для Казахстана его не запускать.

> **Корпус — не «действующее законодательство».** Статус источника (`new`, `upd`, `err`, `yts`, `stp`…)
> сохраняется в метаданных (`status_raw`) и в блоке реквизитов Markdown; фильтровать по нему — позже.

> **robots.txt adilet.zan.kz запрещает `/api/`.** API используется по решению оператора: без флага
> `--i-accept-api-robots-risk` сборщик не запустится. Авторизация, CAPTCHA и блокировки не обходятся:
> при их признаках сбор останавливается с сохранением прогресса.

## Установка (сервер: Python ≥ 3.10)

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

Для продолжения существующего прогресса перенесите папку проекта вместе с `data/`.

## Команды

Полный сбор ru + kk, все статусы (эта же команда продолжает сбор после остановки):

```bash
nohup .venv/bin/python -m adilet_collector crawl --langs ru,kk --i-accept-api-robots-risk > data/crawl.log 2>&1 &
```

Остановка: `kill -INT <pid>` (или Ctrl+C) — незавершённые документы, срезы и страницы каталога вернутся в очередь.

Статистика по языкам, статусам источника и технической полноте:

```bash
.venv/bin/python -m adilet_collector stats --langs ru,kk
```

Отчёт о полноте (в `data/reports/`, не в корпусах):

```bash
.venv/bin/python -m adilet_collector report --langs ru,kk
```

Повтор ошибок / переконвертация сохранённых оригиналов без сети / новый проход сверки каталога:

```bash
.venv/bin/python -m adilet_collector retry-failed --kind all
```

```bash
.venv/bin/python -m adilet_collector reconvert
```

```bash
.venv/bin/python -m adilet_collector recheck-catalog --langs ru,kk
```

Пробный запуск: `crawl ... --max-pages 30 --max-docs 40` (для каталога API `--max-pages` — число поисковых
запросов на язык). Только один язык: `--langs ru` или `--langs kk`.

### Параметры

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `--rps` | 2.0 | **общий** лимит запросов/с на домен: каталог + документы + оба языка + повторы |
| `--catalog-concurrency` / `--catalog-max-concurrency` | 2 / 4 | параллельность каталога (авто-повышение по измерениям) |
| `--start-concurrency` / `--max-concurrency` | 2 / 8 | параллельность документов (авто 2→4→8; выше 8 — только с `--i-measured-above-8`) |
| `--slice-max` | 100 | документов в срезе каталога (100 = одна страница, см. ниже) |
| `--search-sort` | relevance | подтверждённая сортировка поиска |
| `--catalog-source` | api | `old_index` — прежний каталог old.adilet (только действующие) |
| `--doc-transport` | api | `old_html` — страницы old.adilet (~30 с/стр.) |
| `--old-site-fallback` | выкл. | при ошибке API брать страницу old.adilet |
| `--publish-incomplete` | выкл. | неполные — в корпус вместо `data/incomplete/<lang>` |

Второй экземпляр на тех же данных не запустится (файловая блокировка) — лимиты всегда общие.

## Результат

```
data/
  adilet_ru/ adilet_kk/     полностью извлечённые .md ЛЮБОГО статуса: {document_id}_{название}.md
  incomplete/{ru,kk}/       текст есть, но содержательные изображения/файлы не прочитаны
  quarantine/{ru,kk}/{id}/  ошибки извлечения, заглушки без текста, технические аномалии (+ оригинал)
  metadata/{ru,kk}/         {id}.json — метаданные, запись каталога, проверка полноты
  raw/{ru,kk}/              {id}.api.json.gz — исходный JSON API; {id}.html.gz — страницы old.adilet (ранние)
  catalog_raw/{ru,kk}/api/  исходные ответы поиска
  backups/                  копии state.sqlite перед миграциями
  state.sqlite              очередь, состояния, обходы каталога; ключ source + document_id + language
```

Состояния: `validated` (полностью извлечён → корпус), `incomplete`, `failed` (`error_kind`: `download`,
`extract`, `no_text`), `review` (техническая аномалия, например казахская версия с русским текстом),
плюс служебные `discovered/downloading/downloaded/parsed`. **Статус источника на состояние не влияет.**

Метаданные: `source_system: "adilet"`, `jurisdiction: "KZ"`, `language: "ru"|"kk"`, `document_id`
(= `group_number`), `source_uuid` (= `document.id`), `status_raw`, `catalog_record` (запись поиска целиком),
`api` (исходные поля, даты строками, `is_actual` — «не доказательство юридической силы»), `transport`,
`completeness`, `validation`, `warnings`. Название, статус и даты каждого языка берутся только из его ответа.

## Как устроен каталог (проверено на сайте 17.10.2026)

* `page_size` = 100; повтор страницы даёт тот же порядок; `aggregations_enabled=false` не меняет выдачу и
  `total_hits`; `total_pages` в ответе противоречив (11739 / 2348) — не используется. Всего: ru 234 775, kk 236 010.
* **Предел глубины**: `page × page_size ≤ 10 000` (HTTP 422 `PageWindowExceeded`), страница 100 уже пуста.
  Поэтому каталог режется подтверждённым фильтром `filters.date_from/date_to` (фактически по `start_date`,
  принимает ISO-время; диапазон 0001–2999 даёт все документы — без даты нет). Срезы делятся пополам, пока
  в срезе ≤ 100 документов; границы перекрываются на секунду, дубликаты убираются по ID.
* **Порядок `relevance` между страницами нестабилен** (страницы 100+100+13 дали 202 уникальных из 213),
  поэтому по умолчанию срез = одна страница. Если в срезе всё-таки несколько страниц и есть дубликаты —
  срез дробится; неделимый по времени плотный кластер дробится подтверждённым фильтром `status`
  (new/upd/err/yts/stp) со сверкой суммы частей, затем — другими подтверждёнными сортировками.
* **`total_hits` иногда на 1 больше возвращаемых записей** даже на одной странице без дубликатов
  (113 → 112). Такие срезы помечаются `done_short` с размером недостачи и не дробятся бесконечно.
* Каждая страница и каждый срез имеют своё состояние в SQLite; обход = (источник, язык, фильтры,
  сортировка, размер, проход). Обход считается завершённым, только если уникальных ID ≥ `total_hits`
  и нет проблемных срезов; иначе в отчёте — расхождение. Выдача может меняться во время сбора —
  `recheck-catalog` запускает новый проход (готовые документы не скачиваются повторно).
* `has_content=false` у всех записей поиска — документы по нему **не** пропускаются.
* Старый прогресс (old.adilet, только действующие) сохранён, но не считается обходом нового каталога.

## Документы

`GET /api/documents/by-ngr/{id}?language=rus|kaz` (казахский — `kaz`: клиентский код сайта и ответ API).
Проверяются: ID и язык ответа, непустой `text_content`, `is_stub`/`has_content`, язык самого текста.
Исходный JSON сохраняется всегда; заглушки — в quarantine (`no_text`). `text_content` идёт в тот же
конвертер: `#` название, `##` раздел/часть/приложение, `###` глава, `####` статья (рус. и каз. обозначения:
«І бөлім», «1-тарау», «1-бап», «…1-қосымша»); таблицы (сложные — HTML), абсолютные ссылки, `128³`,
`Т<sub>ср</sub>`, примечания и сноски. Проверка полноты сравнивает слова исходного контейнера со словами
готового Markdown; потеря → quarantine. Сверка old.adilet ↔ API на 17 документах: 16 идентичны посимвольно,
1 — другая редакция источника. Даты API хранятся исходными строками; календарная дата = UTC+6 ч с проверкой
по реквизитам (расхождения — в `warnings`); `created_at/updated_at` — метки записи.

## Скорость и срок (оценка)

Ответы: документ ~0,3–0,5 с, поиск ~0,6–3 с, ошибок и 429 в пробах не было. Скорость упирается в общий
лимит **2 запроса/с** (измерено: 200 запросов за 100 с при одновременной работе каталога и документов);
контроллер повышает параллельность только при росте полезной скорости. Нужно ≈ 471 тыс. документов
(ru 234 775 + kk 236 010) + ≈ 15 тыс. поисковых запросов (~32 новых ID на запрос в пробе) ≈ 486 тыс.
запросов → **≈ 67 ч (~2,8 суток) при `--rps 2`**; при `--rps 4` — около 1,4 суток, если сайт не начнёт
отвечать 429 (тогда сборщик сам замедлится). Повышение `--rps` — решение оператора.

## Ограничения полноты

* Содержимое изображений и файлов-приложений не извлекается (OCR нет) → `incomplete`. Декоративными
  считаются только линии/распорки (сторона ≤ 3 px) и маркеры (≤ 12 px).
* `total_hits` поиска иногда больше реально возвращаемых записей (`done_short` в отчёте).
* Не у всех актов есть обе языковые версии; встречаются «казахские» версии с русским текстом (`review`).
* Документы, собранные раньше со страниц old.adilet (~80), сохранены как есть (их `source_url` — old.adilet).
